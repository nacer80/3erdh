# عرض — نسخة HTML محمولة مع ONNX محلي

تعمل هذه النسخة مباشرة من ملف HTML دون Web Speech API ودون خادم localhost. يجري الاستدلال محليًا داخل المتصفح.

## التشغيل

1. افتح `index.html` مباشرة في Chrome أو Edge واضغط بوابة Fullscreen التي تظهر في كل تشغيل.
2. اضغط **اختيار مجلد data** واختر المجلد الرئيسي الذي يحتوي ملفات JSON ومجلد `onnx`.
3. اختر مجلد `data` أو `onnx` الذي يحتوي النماذج.
4. انتظر حتى تظهر حالتا FastConformer وSilero كجاهزتين.
5. اختبر الميكروفون أو ملف MP3، ثم ابدأ التسميع.

## ملفات النماذج

يبحث التطبيق داخل المجلد المحدد عن:

```text
qpc_hafs.json
surah_info.json
ordered_quran_phonemes.json
onnx/zipformer_p_arabic_v3.int8.onnx  # أو v3.1
quran_tokens.txt                       # مضمّن أيضًا
fastconformer_ar_ctc_q8.onnx
qurankarim-fastconformer-mixed.onnx
silero_vad.onnx
tokens.txt                             # FastConformer
```

Sherpa WebAssembly وONNX Runtime وملفا الرموز مضمّنة داخل HTML. أما `qpc_hafs.json` و`surah_info.json` و`ordered_quran_phonemes.json` فتُقرأ مباشرة من مجلد `data` ولا تُكرر داخل HTML. الوضع الذكي يستخدم Zipformer، ويظل FastConformer احتياطيًا.

## خط المعالجة

```text
الميكروفون أو ملف صوتي
→ PCM mono
→ resample إلى 16 kHz
→ Silero VAD
→ بوابة طاقة احتياطية عند الإشارة الواضحة
→ 80-bin Log-Mel Filterbank
→ FastConformer ONNX
→ CTC decoding
→ مطابقة متسلسلة مع كلمات السورة
```

## الواجهة والإعداد الأول

- اسم المشروع هو **عرض**.
- زر المساعدة `؟` بجانب **اختيار مجلد النماذج** يعرض المسار المنطقي الثابت `/data/onnx/` والملفات المطلوبة وحجمها واسم نموذج FastConformer النشط.
- يطلب التطبيق اختيار الميكروفون في المرة الأولى فقط، ثم يحفظ `deviceId` والاسم ويحتفظ بتدفق الميكروفون أثناء الزيارة حتى لا يعيد نافذة الاختيار مع البحث أو التصحيح الصوتي. يبقى زر الاختبار متاحًا لتغييره يدويًا.
- تحولت إحصاءات الجلسة إلى سطر واحد: الكلمات الصحيحة، الدقة، الأخطاء، والتقدم.
- صُغّرت تسميات الواجهة قليلًا دون تصغير النص القرآني.
- جميع التنبيهات الخفيفة ورسائل إعادة الجلسة ومسح السجل والأخطاء تظهر داخل شريط الحالة في الشاشة الرئيسية؛ أزيلت نوافذ `alert/confirm` والتنبيه العائم.
- تستخدم البطاقة الحمراء نفس أسلوب البطاقة الصفراء: يظهر Tooltip بعنوان **مشكلة تطابق** عند تمرير المؤشر أو تركيز لوحة المفاتيح، بدل إضافة لابل دائم فوق الكلمة.
- عند العودة للقراءة بعد صمت طويل يُعاد ضبط مخزن Sherpa/FastConformer تلقائيًا، مع مراقبة AudioContext وتدفق الميكروفون واستعادته دون فقد موضع القراءة.
- بعد اختيار مجلد `data` أو رفع ملف صوتي يحاول التطبيق الدخول إلى Fullscreen مباشرة أثناء حدث اختيار الملف.
- تظهر بوابة **بدء التطبيق بملء الشاشة** في كل تشغيل لأن المتصفح يتطلب نقرة مستخدم، ويبقى قفل Fullscreen فعالًا ويحاول استعادته تلقائيًا ما لم يضغط المستخدم زر الخروج `✕`.
- أثناء تشغيل الميكروفون تتمدد بطاقة المصحف ويُوسّط النص القرآني رأسيًا وأفقيًا داخل مساحة العرض، ثم يعود التخطيط العادي عند إيقاف الاستماع.
- يدعم البحث في فهرس السور الأرقام الغربية والعربية مثل `114` و`١١٤`، مع زر بحث صوتي داخل صفحة المصحف. بعد البحث الصوتي يظهر الاسم العربي للسورة ورقمها ونسبة المطابقة في رأس صفحة المصحف.
- تظهر آيات نتائج البحث باللون الأبيض ورقم الآية باللون الذهبي.
- على الهاتف يحاول التطبيق طلب الميكروفون مباشرة قبل تحميل النموذج وتهيئة AudioContext أثناء نقرة المستخدم. وإذا كان `getUserMedia` محظورًا بسبب غياب HTTPS يظهر زر **تسجيل مقطع من الهاتف** الذي يستخدم مسجل النظام ثم يحلل الملف محليًا، دون تغيير سلوك نسخة الكمبيوتر.

## المحرك الذكي Zipformer / Sherpa

أضيف محرك تعرف ثانٍ متكامل مستفاد من [`recite_quran`](https://pub.dev/packages/recite_quran):

```text
الميكروفون 16kHz
→ مقاطع 320ms
→ Sherpa ONNX WebAssembly
→ zipformer_p_arabic_v3.int8.onnx
→ فونيمات قرآنية مع timestamps
→ Semi-global DTW وكلفة الالتباسات الصوتية
→ مطابقة الكلمات والحركات وأحكام التجويد
```

ملفات Sherpa WebAssembly و`quran_tokens.txt` موجودة في الحزمة. ضع نموذج Zipformer في:

```text
/data/onnx/zipformer_p_arabic_v3.int8.onnx
```

أو النسخة الأحدث:

```text
/data/onnx/zipformer_p_arabic_v3.1.int8.onnx
```

لا يحتاج الوضع الذكي إلى خادم: تم تضمين Sherpa JavaScript وملف WebAssembly و`quran_tokens.txt` داخل `index.html`. افتح الملف مباشرة واختر مجلد `data` الرئيسي؛ لا توجد ملفات تشغيل BAT أو Python في الحزمة.

- الوضع الذكي هو الافتراضي، ويُفضّل تلقائيًا `zipformer_p_arabic_v3.1.int8.onnx` ثم v3.
- تُستخدم محاذاة DTW حرفًا فونيميًا مع مصفوفة التباسات مثل `س/ص` و`ت/ط` و`ق/ك`.
- يتم تجاهل أي خرج يتكون من حرف أو فونيم واحد فقط، ولا يُحسب خطأً.
- الانتقال التلقائي السلس يحافظ على موضع القراءة والميكروفون: Zipformer ← Mixed ← Q8، ويعود إلى Zipformer إذا أصبح جاهزًا أثناء الجلسة.
- الأخضر = مطابقة صحيحة، الأصفر = تنبيه تجويد، الأحمر = حذف/استبدال فونيمي واضح.
- تقارير الأخطاء والحركات والتجويد تمنح فرصة تصحيح. يعمل تقرير التجويد الآن مثل تقرير الحركات: اضغط **تصحيح التجويد** لفتح لوحة التصحيح، ثم اضغط **إعادة القراءة والتصحيح** داخلها. تم إصلاح تمرير حدث الزر الذي كان يُفسر خطأً كفهرس كلمة. بعدها يفعّل Zipformer والميكروفون وينتظر الكلمة حتى 18 ثانية ثم يعيد DTW وقياس المد/الغنة/الشدة ويحدّث اللون والتقرير.

استُفيد من بنية وقواعد مشروع `recite_quran` وبياناته الفونيمية، مع الالتزام بشرطه أن يبقى الاستخدام مجانيًا وغير تجاري. توجد نسخة الترخيص في `data/sherpa/RECITE_QURAN_LICENSE.txt`، ويجب التنبيه للمستخدمين أن التقييم الآلي قد يخطئ ولا يستبدل معلّمًا مؤهلًا.

- أُضيفت بيانات فونيمية مضغوطة لجميع كلمات القرآن مستخرجة من `ordered_quran_phonemes.json`.
- تُحدد قواعد المدود 1–7 لكل كلمة، مع الشدة (9) وغنة النون والميم المشددتين (10).
- أصبح CTC decoder يحتفظ بتوقيت كل spike ويستخرج وقت بداية ونهاية كل كلمة بدل إرجاع النص وحده.
- الحالات المرئية تتبع فكرة المشروع: أخضر للكلمة الصحيحة، أصفر للكلمة الصحيحة مع تنبيه تجويد، وأحمر للخطأ اللفظي.
- أُضيفت أوضاع سهل/متوسط/صارم بزمن حركة أساسي `0.15/0.20/0.25` ثانية.
- يفحص **تقرير التجويد** المد الطبيعي، المنفصل، المتصل، العارض، اللين، اللازم، الشدة والغنة، ويعرض المطلوب والمدة المرصودة.

في الوضع الذكي يستخدم التطبيق Zipformer وتوقيت الفونيمات ومحاذاة DTW لفحص موضع المد والغنة والشدة داخل الكلمة. إذا تعذر Zipformer وانتقل إلى FastConformer، يتحول تقرير التجويد تلقائيًا إلى الفحص التحفظي المبني على مدة الكلمة كاملة.

## التعرف على الحركات والتشكيل

- أصبح الوضع التلقائي يفضّل نموذج `qurankarim-fastconformer-mixed.onnx` لدقة أعلى، ثم ينتقل إلى Q8 عند الحاجة.
- رُفعت نافذة السياق الصوتي إلى 4.2 ثوانٍ على الأقل، وزيد تداخل المقاطع إلى 800ms لتقليل قطع الكلمات والحركات عند الحدود.
- يحتفظ التطبيق بخرج CTC المشكول قبل التطبيع، ويستخدم نسخة غير مشكلة فقط لمحاذاة الكلمات.
- بعد مطابقة الكلمة يحلل الفتحة والضمة والكسرة والسكون والشدة والتنوين والألف الخنجرية حرفًا حرفًا.
- يفرق التقرير بين **خطأ صريح** عندما ينتج النموذج حركة مختلفة، و**حركة غير ملتقطة** تحتاج مراجعة ولا تُعد حكمًا قطعيًا.
- تظهر الكلمات ذات أخطاء الحركات بخط سفلي برتقالي داخل بطاقة المصحف، مع زر **تقرير الحركات** وتفاصيل المتوقع والمسموع.

## البحث والتقارير

- اسم قسم القراءة أصبح **المصحف حفص**.
- **بحث صوتي عن السورة:** انطق اسم السورة من نافذة اختيار السور، ويعرض التطبيق أقرب نتيجة بالمطابقة الضبابية.
- **بحث صوتي في الآيات:** اقرأ جزءًا متتابعًا من الآية، ويبحث التطبيق محليًا في 6236 آية ويعرض أفضل النتائج مع نسبة المطابقة.
- يدعم بحث الآيات الإدخال النصي أيضًا، والانتقال المباشر إلى الآية وتمييزها داخل المصحف.
- **تقرير الأخطاء:** يسجل الكلمة المطلوبة، ما سمعه FastConformer، عدد المحاولات، وأفضل توافق.
- يمكن تصحيح كل كلمة يدويًا أو صوتيًا من التقرير؛ وتتحول إلى حالة «تم التصحيح» عند نجاح المحاولة.
- يظهر اختصار تقرير الأخطاء أيضًا بعد اكتمال السورة.

## مراجعة الإعدادات والنماذج

- أُعيد تفعيل `filter: blur(var(--blur))` و`-webkit-filter` للكلمات المخفية؛ يعمل شريط قوة التمويه مباشرة من 2 إلى 12 بكسل.
- تُنقح القيم المخزنة تلقائيًا ضمن الحدود الصحيحة، مع زر **استعادة الإعدادات الافتراضية** يحافظ على الميكروفون المختار.
- تغيير FastConformer من Mixed إلى Q8 أو العكس لا يحتاج إعادة تحميل الصفحة، ويستخدم الانتقال السلس عند وجود جلسة نشطة.
- تعطيل الحركات أو التجويد يزيل ألوانهما وعداداتهما فورًا دون حذف التقرير المسجل.
- عند اختيار مجلد `data` يتحقق التطبيق من وجود وأحجام Zipformer وFastConformer وSilero وملفات JSON قبل محاولة التحميل.

## التحسينات التشخيصية

- **اختبار الميكروفون:** يعرض جميع أجهزة الإدخال ومؤشر dBFS حي، ثم يحفظ الجهاز المختار خلال الجلسة.
- **مؤشر مباشر:** يعرض `dBFS` ونتيجة VAD في شاشة التسميع.
- **اختبار MP3:** يفك الملف محليًا، يقسمه إلى مقاطع متداخلة، ويشغّل FastConformer حتى عند انخفاض VAD لأغراض التشخيص.
- **نتيجة الملف:** تعرض المدة، أعلى VAD، زمن الاستدلال، عدد مرات تجاوز VAD، والنص المتعرف عليه.
- **سجل التشخيص:** يعرض أسماء الملفات وأحجامها، مدخلات ومخرجات ONNX، مستوى كل مقطع، وخرج FastConformer، مع إمكانية النسخ.
- **بوابة الطاقة:** إذا كانت الإشارة أعلى من `-50 dBFS` لا يسمح التطبيق لـSilero بمنع FastConformer نهائيًا.

## ملاحظات

- يجب اختيار مجلد النماذج مجددًا بعد إعادة تحميل الصفحة بسبب حماية المتصفح.
- دعم MP3 يعتمد على قدرة المتصفح على فك الترميز؛ Chrome وEdge هما الخياران الموصى بهما.
- عند التشغيل المباشر يستخدم التطبيق ملفات WASM المضمّنة. إذا رفض المتصفح الميكروفون عند `file://` فتحقق من أذونات الميكروفون، أو استخدم زر تسجيل مقطع من الهاتف.
- التعرف النصي ليس بديلًا عن معلّم متقن لأحكام التجويد والمخارج.
